# 2.1 기획안 — 네 번째 탭 "다음 경기" (접음, 2026-11-18)

> 구현·테스트까지 했으나 오너가 "별로다"로 접었다. 코드는 커밋 전에 되돌렸다. 채택안은 PLAN_2.1_CHALLENGES_TAB.md.
> 접은 이유로 본 것: 영상 앱인데 탭에 영상이 없다 · 일정을 먼저 입력해야 내용이 생긴다 · 알림이 일을 하면 탭은 안 열린다.

## 목표
사용자가 앱을 더 자주 열게 한다. 단 Ribatto의 사용 빈도는 **경기 빈도(주 1~3회)에 묶여 있다**.
그래서 지표를 "매일 열기"가 아니라 둘로 나눈다.
1. **촬영률** — 실제로 친 경기를 빠짐없이 찍어 오게 한다(루프의 가장 약한 고리: 삼각대 챙기기를 잊음).
2. **경기 사이 재방문** — 경기 없는 날에도 열 만한 작고 진짜인 이유.

## 근거 (시장조사·전략 에이전트, 2026-11-17)
- Strava는 "기록(Record)"을 상시 탭으로 둔다. 연속 기록은 **주 단위**(월~일)다.
- 끊긴 연속 기록은 이탈을 부르고, "놓쳤어요" 알림은 효과가 없으며, 돈·광고로 복구하는 연속 기록은 신뢰를 깎는다(JCR 2023). Khan Academy는 일 단위 연속 기록을 없앴다가 주 단위로 되살렸다.
- 경기 사이 기능을 사용자가 직접 요청한 글은 못 찾았다(근거 약함). 경기 일지 앱은 많지만 수요 증거는 아니다.
- 서버 없이 되는 것: 로컬 알림(이미 BackgroundWork에 있음), 위젯, Live Activity(확장 타깃 필요).
- 드릴 탭은 제외 — 9개 언어 콘텐츠를 1인이 계속 써야 하고, 했는지 확인할 방법이 없다.

## 탭 구성 (위에서부터)
1. **다음 경기 카드** — "수요일 19:00 · 리버사이드 코트".
   - 지난 경기 기록(촬영 시각·요일·장소)에서 가장 잦은 요일·시간을 추정해 미리 채워 두고, 사용자는 확인만 한다.
   - 경기 기록이 없으면 요일·시간을 직접 고른다. 요일은 여러 개 가능.
2. **촬영 시작**(주 버튼) · 가져오기(보조) — 기존 VideoRecorder / 사진 가져오기 흐름 재사용.
3. **알림 켜기**(옵트인)
   - 경기 30분 전: "오늘 경기 — 삼각대 챙기세요".
   - 경기 시작 3시간 뒤: "오늘 경기 영상 가져올까요?" 그날 경기가 이미 들어와 있으면 보내지 않는다.
   - 앞으로 2주치를 개별 예약하고, 앱이 앞에 올 때·가져올 때 다시 짠다.
   - 3번 연속 그 시간에 경기가 안 들어오면 알림을 쉬고, 탭에 "알림 쉬는 중 · 다시 켜기"를 보인다.
4. **주간 기록** — 최근 8주 점 + "N주 연속".
   - 앱이 실제로 감지한 경기만 센다. 복구도 "놓쳤어요" 문구도 없다.
5. **다시 볼 랠리 하나** — 즐겨찾기·🔥·최장 랠리 중 하루에 하나를 돌려 보여 준다(포스터 + 탭하면 재생).
   - 경기 없는 날의 유일한 정직한 보상: 내 최고 장면.
6. **다음엔 이것** — 한 줄 메모("백핸드 크로스"). 다음 경기를 가져오면 그 세션에 붙고 칸은 비워진다.
   - 세션 화면 위쪽에 보인다(경기 끝나고 목표와 증거를 나란히).

## 범위 밖 (2단계)
- 홈 화면 위젯(다음 경기 / 내 랠리 포스터) — 위젯 확장 타깃 + App Group이 필요하다.
- Live Activity, HealthKit, 캘린더 연동.

## 성공 판단
앱 안 분석 SDK가 없다. App Store Connect의 앱 분석(동의한 사용자만)에서 세션 수·보존율을 본다.
사용자가 거의 없으므로 판단은 첫 50명 이후로 미룬다.

## 타당성 회의 결과 (2026-11-17) → 구현한 범위

- 비판 검토: "경기 0~1개 신규 사용자에게는 폼 + 빈 카드뿐이라 탭이 없느니만 못하다. 라이브러리 카드로." → **줄여서 진행**.
- 기술 검토: 새 타깃·권한 없이 기존 코드로 가능(약 800줄).
- 오너 결정: **축소한 4번째 탭**.

| 초안 항목 | 결정 | 이유 |
|---|---|---|
| 다음 경기 카드 | 유지 · 첫 화면은 "언제 치세요?" 요일·시간 고르기 | 추정은 최근 8주 같은 요일 ±90분 3회 이상일 때만 제안. capturedAt 없는 세션(가져온 시각)은 제외 |
| 촬영·가져오기 | 유지 | 라이브러리 탭으로 넘겨 기존 흐름 재사용, 녹화 후 새 세션으로 착지 |
| 30분 전 알림 | 유지 · 별도 토글, 기본 꺼짐, 일정 저장 후에만 보임 | 처리 완료 알림 권한을 동의로 재사용하지 않음. 거부 상태면 설정 열기 |
| 3시간 뒤 알림 | **삭제** | 귀가·샤워 중이고, 따로 찍은 영상은 아직 폰에 없다. 잔소리형 알림은 효과 없음 |
| 3번 연속 놓치면 쉼 | 요일별로 | 월·수·금 중 한 번만 치는 사람이 5일 만에 꺼지지 않게 |
| 주간 기록 | 유지 · 3주 데이터 전엔 숨김 · 감지 여부와 무관하게 찍은 날 기준 | 감지 실패·비·부상을 벌하지 않는다 |
| 오늘의 랠리 | **삭제** | 세션 히어로와 중복, 클립 비우면 깨짐 |
| 다음엔 이것 메모 | **삭제** | 경기 전에 폰으로 메모하는 사람은 드물고, 비면 두 화면에 빈 칸 |

## 테스트 (시뮬레이터, 2026-11-17)
- 빈 상태 → 요일 2개·19:00 저장 → 다음 경기 카드("수요일 오후 7:00 · 21시간 후") 확인. iPhone 17 Pro Max · SE(작은 화면) · 독일어.
- 알림: 토글을 켤 때만 권한 프롬프트 → 허용 → 정확히 30분 전에 배너 도착. 앱을 종료한 뒤 다시 예약된 알림도 도착. 거부 상태에서는 설정 열기 창.
- 촬영 버튼 → 라이브러리 탭으로 전환 후 녹화 흐름(시뮬레이터는 카메라 없음 알림), 사진 버튼 → 사진 선택기.
- 경기한 주: 임시 세션 3개(지난 화요일들)로 "최근 8주 중 3주 · 3주 연속" 확인 후 삭제.
- 일정 로직은 Debug 실행마다 `MatchSchedule.selfCheck()` 단언 통과.
- **미확인**: 알림 탭 → 다음 경기 탭 이동(시뮬레이터 잠금 화면에서 주입한 탭으로는 알림이 열리지 않았다), 실기기, 앱 내 녹화 영상의 capturedAt이 시작 시각인지 끝 시각인지.
